# Example Security Console
## Security Event Investigation User Guide

Use Example Security Console to review, assign, investigate, and resolve security events generated by your organization's monitored endpoints and cloud services.

## About security events

A security event records an activity that matched a monitoring or protection policy. Each event includes the affected user or device, the policy that generated the event, activity details, and an investigation status.

Use the **Events** workspace to identify activity that requires review and to document the outcome of the investigation.

## Required role

You need the **Security Analyst** role to view and update events. You need the **Security Administrator** role to change policy settings or manage notification rules.

## Open the Events workspace

1. Sign in to Example Security Console.
2. Click **Investigations** > **Events**.

The event list opens in the main workspace. The right-side panel displays event details when you select an event.

> **Tip:** Collapse the right-side panel when reviewing a large event list. Select an event again to reopen its details.

## Filter security events

Use filters to reduce the event list to the activity you need to review.

1. In the **Events** workspace, click **Filter**.
2. Select a filter type, such as **Time Range**, **Severity**, **Status**, **User**, **Endpoint**, or **Policy**.
3. Select or enter a filter value.
4. Click **Apply**.

The event list refreshes and displays only events that match all selected filters.

| Filter | Use it to find |
| --- | --- |
| **Time Range** | Events that occurred during a specific period. |
| **Severity** | Events that require a particular urgency level. |
| **Status** | New, in-progress, resolved, or closed events. |
| **User** | Events associated with a specific user. |
| **Endpoint** | Events generated by a particular device. |
| **Policy** | Events generated by a specific monitoring or protection policy. |

To remove a filter, click **Clear Filters**.

## Review event details

1. Select an event in the event list.
2. Review the summary in the right-side panel.
3. Expand **Activity Details**, **Policy Match**, or **Event Timeline** to review the available information.

| Section | Description |
| --- | --- |
| **Summary** | Event ID, severity, status, user, endpoint, and timestamp. |
| **Activity Details** | The activity that generated the event and the relevant destination or resource. |
| **Policy Match** | The policy condition and action associated with the event. |
| **Event Timeline** | Status changes, assignments, analyst notes, and related system activity. |

> **Important:** Treat event details as sensitive information. Follow your organization's handling requirements before copying, exporting, or sharing data.

## Set severity and assign an event

Set a severity level and assign an owner so the event receives appropriate attention.

1. Select the event.
2. In the right-side panel, select a value from the **Severity** list: **Low**, **Medium**, **High**, or **Critical**.
3. Select a person from the **Assignee** list.
4. Click **Save**.

Expected result: the event list updates with the selected severity and assignee. The change also appears in **Event Timeline**.

## Add an investigation note

Use notes to record the investigation result, actions taken, or information needed from another team.

1. Select the event.
2. In the right-side panel, expand **Notes**.
3. Click **Add Note**.
4. Enter the investigation update.
5. Click **Save Note**.

Include factual, time-specific information. For example: `Confirmed that the transfer was approved by the data owner at 14:30 UTC.`

## Resolve or reopen an event

Resolve an event after you complete the investigation and document the outcome.

1. Select the event.
2. Select **Resolved** from the **Status** list.
3. Select a value from the **Resolution** list.
4. Add a final note that explains the outcome.
5. Click **Save**.

Expected result: the event status changes to **Resolved**. Resolved events remain available in search and reports.

To continue an investigation, select the event and change the **Status** to **In Progress**.

## Find related events

Use related events to determine whether the activity is isolated or part of a broader pattern.

1. Open an event.
2. In **Activity Details**, select the user, endpoint, or policy name.
3. Click **View Related Events**.
4. Adjust the **Time Range** filter as needed.

Review the results for repeated activity, multiple affected endpoints, or changes in severity.

## Export event results

Export filtered results for a case record, audit review, or approved stakeholder report.

1. Apply the filters you want to export.
2. Click **Export**.
3. Select **CSV** or **PDF**.
4. Select the fields to include.
5. Click **Generate Export**.

Expected result: Example Security Console prepares the export and displays it in the **Downloads** area.

> **Important:** Exports can contain user, endpoint, and policy information. Store exports only in approved locations and follow your organization's retention requirements.

## Troubleshooting

| Issue | Action |
| --- | --- |
| No events appear | Clear filters, confirm the selected time range, and verify that you have the **Security Analyst** role. |
| Event details do not open | Select the event again. If the issue continues, refresh the page and confirm network connectivity. |
| Cannot change severity or status | Confirm that you have permission to update events and that another analyst has not locked the event for editing. |
| Export is unavailable | Reduce the selected time range or number of events, then generate the export again. |
| Recent activity is missing | Confirm that the source endpoint or cloud service is connected and has completed a recent check-in. |

## Next steps

After resolving an event, review related events and policy results. If you identify recurring legitimate activity, work with the policy owner to refine the policy or document an approved exception.
